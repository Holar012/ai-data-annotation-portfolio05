# Annotation Guideline Principles

These are the principles I use when working on annotation tasks:

1. **Project rules come first.** I follow the written guideline even when a different label may seem intuitive.
2. **Evidence over assumption.** I label only what is supported by the data.
3. **Consistency matters.** Similar examples should receive similar treatment.
4. **Ambiguity should be handled conservatively.** I avoid inventing facts or relationships.
5. **Boundary precision matters.** Incorrect spans or frame boundaries can make an otherwise correct annotation unusable.
6. **Quality review is part of annotation.** I check my work before submission.
7. **Confidentiality matters.** Client or project data should not be added to public portfolios without permission.
